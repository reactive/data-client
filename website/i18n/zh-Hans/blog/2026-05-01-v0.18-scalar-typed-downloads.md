v0.18 聚焦于三件事：对随请求上下文变化的值进行更丰富的数据建模、更简单的类型化下载，以及更贴近真实 API 过滤条件的集合匹配。

**新特性：**

- [Scalar schema](/blog/2026/05/01/v0.18-scalar-typed-downloads#scalar) - 随视角（lens）变化的实体字段（例如特定投资组合的数值），且永不修改底层实体
- [RestEndpoint `content` 属性](/blog/2026/05/01/v0.18-scalar-typed-downloads#content-property) - 只用一个属性即可实现类型化文件下载、文本响应和流式传输
- [resource() `nonFilterArgumentKeys`](/blog/2026/05/01/v0.18-scalar-typed-downloads#non-filter-argument-keys) - 排序/分页参数不再把你的 [Collection](/rest/api/Collection) 拆散

**其他改进：**

- [二进制 Content-Type 自动检测](/blog/2026/05/01/v0.18-scalar-typed-downloads#binary-auto-detection) - 图片、PDF 及其他二进制响应无需任何配置即可自动处理（[#3868](https://github.com/reactive/data-client/pull/3868)）
- [Collection 扩展方法的 body 类型与 HTTP 方法语义一致](/rest/api/Collection) - PATCH 扩展方法（`.move`、`.remove`）接受部分 body；独立的 [RestEndpoint](/rest/api/RestEndpoint) 会从 [Collection](/rest/api/Collection) 的实体 schema 推导出类型化的 body（[#3910](https://github.com/reactive/data-client/pull/3910)）
- 从 `@data-client/endpoint` 和 `@data-client/rest` 导出 [`CollectionOptions`](/rest/api/Collection)，用于类型化地构造 [Collection](/rest/api/Collection)（[#3904](https://github.com/reactive/data-client/pull/3904)）

## Scalar {#scalar}

[Scalar](/rest/api/Scalar) 用于处理那些取值依赖运行时“视角”（lens）的 [Entity](/rest/api/Entity) 字段——比如
当前选中的投资组合、货币或区域设置。多个组件可以同时通过不同视角渲染**同一个**实体，
各自看到正确的值，而实体本身始终不变。随视角变化的值存放在单独的单元格表中，
并在反规范化时根据 endpoint 参数进行关联。

切换投资组合时 `name` 和 `price` 的引用保持稳定，因为 `Company` 实体本身
从未改变——改变的只是当前视角所选中的 [`Scalar`](/rest/api/Scalar) 单元格。同一个 [`Scalar`](/rest/api/Scalar)
实例既可以作为 [`Entity.schema`](/rest/api/Entity#schema) 字段使用（父实体从访问过程中推断），也可以独立用在 [`Values`](/rest/api/Values)、[`[Scalar]`](/rest/api/Array)
或 [`Collection([Scalar])`](/rest/api/Collection) 中，以实现低成本的仅刷新列操作（通过
[`entity`](/rest/api/Scalar#entity) 显式绑定实体）。单元格的 pk 由映射键派生，或通过
[`Scalar.entityPk()`](/rest/api/Scalar#entityPk) 得到，后者默认使用 [`Entity.pk()`](/rest/api/Entity#pk)，因此自定义主键和
复合主键无需重写即可正常工作。

规范化后的 store 保持实体稳定，并把视角单元格分开存放：

```
entities['Company']['1'] = {
  id: '1',
  price: 145.20,
  pct_equity: ['1', 'pct_equity', 'Company'],
  shares: ['1', 'shares', 'Company'],
}

entities['Scalar(portfolio)']['Company|1|A'] = { pct_equity: 0.50, shares: 10000 }
entities['Scalar(portfolio)']['Company|1|B'] = { pct_equity: 0.30, shares: 6000 }
```

示例将 `getCompanies` 与一个低成本的、仅刷新视角数据的 `getPortfolioColumns` 配对，二者写入
同一个单元格表——完整的缓存行为讲解请参阅 [Scalar 文档](/rest/api/Scalar)。

[`Scalar`](/rest/api/Scalar) 还实现了 [queryKey](/rest/api/Scalar#queryKey)，因此可以直接参与
[useQuery](/docs/api/useQuery)、[Controller.get](/docs/api/Controller#get) 和 [schema.Query](/rest/api/Query)——
即完整的 [Queryable](/rest/api/schema#queryable) 能力——枚举当前视角下的所有单元格。

[#3887](https://github.com/reactive/data-client/pull/3887) - [Scalar 文档](/rest/api/Scalar)

## RestEndpoint `content` 属性 {#content-property}

[RestEndpoint](/rest/api/RestEndpoint) 现在接受一个 [`content`](/rest/api/RestEndpoint#content) 属性，用于控制
响应体的解析方式。返回类型会根据该值自动推断，并且对于非 JSON 的内容类型，`schema`
在类型层面被约束为 `undefined`。

```typescript
import { RestEndpoint } from '@data-client/rest';

const downloadFile = new RestEndpoint({
  path: '/files/:id/download',
  // highlight-next-line
  content: 'blob',
  dataExpiryLength: 0,
});

// Return type is Blob — inferred from content, no explicit generics needed
const blob: Blob = await ctrl.fetch(downloadFile, { id: '123' });
```

以前，文件下载需要冗长地重写 `parseResponse`。现在只需一个属性。

| 值 | 解析方式 | 返回类型 |
|---|---|---|
| `'json'` | `response.json()` | `any` |
| `'blob'` | `response.blob()` | `Blob` |
| `'text'` | `response.text()` | `string` |
| `'arrayBuffer'` | `response.arrayBuffer()` | `ArrayBuffer` |
| `'stream'` | `response.body` | `ReadableStream<Uint8Array>` |

将 `content` 设为非 JSON 的值会在类型层面强制要求 `schema: undefined`，因为二进制数据无法
被规范化。如果不小心使用了可规范化的 schema，运行时检查会给出清晰的错误信息。

可与 [`extend()`](/rest/api/RestEndpoint#extend) 和[子类](/rest/api/RestEndpoint#inheritance)配合使用：

```typescript
// Extend a JSON endpoint into a blob downloader
const download = jsonEndpoint.extend({
  content: 'blob',
  schema: undefined,
});

// Subclass for a reusable blob endpoint type
class BlobEndpoint<O extends RestGenerics = any> extends RestEndpoint<O> {
  content = 'blob' as const;
}
```

[#3868](https://github.com/reactive/data-client/pull/3868) - [`content` 文档](/rest/api/RestEndpoint#content)

## resource() `nonFilterArgumentKeys` {#non-filter-argument-keys}

[`nonFilterArgumentKeys`](/rest/api/Collection#nonFilterArgumentKeys) 让 [resource()](/rest/api/resource)
可以声明哪些参数键*不*用于过滤集合结果——通常是排序、
分页或显示选项。没有它的话，每一组不同的排序或分页参数都会创建一个独立的
[Collection](/rest/api/Collection) 分桶，新创建的条目也不会出现在使用了
不同排序参数的列表中，即便底层数据本应匹配。

```ts
import { Entity, resource } from '@data-client/rest';

class Post extends Entity {
  id = '';
  title = '';
  group = '';
  author = '';
}

const PostResource = resource({
  path: '/:group/posts/:id',
  searchParams: {} as { orderBy?: string; author?: string },
  schema: Post,
  // highlight-next-line
  nonFilterArgumentKeys: ['orderBy'],
});
```

现在 `group` 和 `author` 是过滤键（它们划分出各自独立的 [Collection](/rest/api/Collection)），而 `orderBy` 是
共享的——`PostResource.getList.push()` 会把新帖子添加到给定 `{ group, author }` 分桶的
*所有* `orderBy` 变体中。

接受 `string[]`、`RegExp` 或谓词函数：

```ts
nonFilterArgumentKeys: /^(orderBy|page|cursor)$/,
```

[#3914](https://github.com/reactive/data-client/pull/3914) - [`nonFilterArgumentKeys` 文档](/rest/api/Collection#nonFilterArgumentKeys)

## 二进制 Content-Type 自动检测 {#binary-auto-detection}

当未设置 `content` 时，[`parseResponse`](/rest/api/RestEndpoint#parseResponse) 现在会自动检测二进制
Content-Type 并返回 `response.blob()`，而不是通过 `.text()` 损坏数据。

诸如 `image/*`、`audio/*`、`video/*`、`font/*`、`application/octet-stream`、`application/pdf` 等
二进制类型现在都会自动处理。类文本类型（`text/*`、XML、HTML、JavaScript、CSS 等）继续
使用原有的文本 fallback，并附带感知 schema 的错误信息。

这意味着带有正确 Content-Type 头并提供二进制数据的 endpoint 无需任何配置即可工作：

```typescript
const ep = new RestEndpoint({
  path: '/avatars/:id',
});
// Server responds with Content-Type: image/png
// → automatically returns a Blob (previously corrupted via .text())
```

[#3868](https://github.com/reactive/data-client/pull/3868)

### Schema.denormalize() 接收 delegate {#denormalize-delegate}

如果你没有实现自定义 [Schema](/rest/api/SchemaSimple) 类，可以跳过本节。

[`Schema.denormalize()`](/rest/api/SchemaSimple) 现在的签名是 `(input, delegate)`，取代了以前的 3 参数
签名 `(input, args, unvisit)`。新的
[`IDenormalizeDelegate`](/rest/api/SchemaSimple) 暴露了 `unvisit`、`args` 以及新的 `argsKey(fn)` 辅助方法。
[#3887](https://github.com/reactive/data-client/pull/3887)

<DiffEditor>

```ts title="Before"
import { Entity } from '@data-client/rest';

class Wrapper {
  denormalize(
    input: {},
    args: readonly any[],
    unvisit: (s: any, v: any) => any,
  ) {
    const value = unvisit(this.schema, input);
    return this.process(value, ...args);
  }
}
```

```ts title="After"
import { Entity, type IDenormalizeDelegate } from '@data-client/rest';

class Wrapper {
  denormalize(input: {}, delegate: IDenormalizeDelegate) {
    const value = delegate.unvisit(this.schema, input);
    return this.process(value, ...delegate.args);
  }
}
```

</DiffEditor>

codemod 能处理类方法、对象方法、函数声明、TypeScript 接口
签名，以及透传式的 `someSchema.denormalize(input, args, unvisit)` 调用。它还会把
[`IDenormalizeDelegate`](/rest/api/SchemaSimple) 以内联 `type` 说明符的形式添加到你现有的
`@data-client/*` 导入中（找不到时则新建一行 `import type`）。

#### 依赖参数的输出 {#args-dependent-output}

直接读取 [`delegate.args`](/rest/api/SchemaSimple) **不会**参与记忆化。如果你的 schema 的*输出*
依赖这些参数（例如一个视角），请通过 [`delegate.argsKey(fn)`](/rest/api/SchemaSimple) 声明这一依赖，
以便缓存正确分桶。

<DiffEditor caption="codemod 无法推断这个依赖，所以请手动更新这些 schema。">

```ts title="Before"
class LensSchema {
  denormalize(input, args, unvisit) {
    const lens = args[0]?.portfolio;
    return this.lookup(input, lens);
  }
}
```

```ts title="After"
class LensSchema {
  constructor({ lens }) {
    // callout: The function reference is the cache key, so set it once here (or at module scope). An inline arrow would miss the cache on every call.
    this.lensSelector = lens;
  }
  denormalize(input, delegate) {
    // callout: `argsKey` returns `fn(args)` and records the dependency for memoization.
    const lens = delegate.argsKey(this.lensSelector);
    return this.lookup(input, lens);
  }
}
```

</DiffEditor>

完整示例请参阅 [Scalar](/rest/api/Scalar)。

### Schema.normalize() 接收 delegate {#normalize-delegate}

如果你没有实现自定义 [Schema](/rest/api/SchemaSimple) 类，可以跳过本节。

[`Schema.normalize()`](/rest/api/SchemaSimple) 现在从
[`INormalizeDelegate`](/rest/api/SchemaSimple) 读取 endpoint 参数和递归访问器，与新的 [denormalize delegate](/rest/api/SchemaSimple) 的形式保持一致。
以前的签名是 `(input, parent, key, args, visit, delegate, parentEntity?)`；
新的签名是 `(input, parent, key, delegate, parentEntity?)`。
[#3934](https://github.com/reactive/data-client/pull/3934)

<DiffEditor>

```ts title="Before"
import type { INormalizeDelegate, Visit } from '@data-client/rest';

class Wrapper {
  normalize(
    input: any,
    parent: any,
    key: string,
    args: readonly any[],
    visit: Visit,
    delegate: INormalizeDelegate,
  ) {
    const normalized = visit(this.schema, input.value, input, 'value', args);
    delegate.mergeEntity(this, this.pk(input, parent, key, args), normalized);
    return normalized;
  }
}
```

```ts title="After"
import type { INormalizeDelegate } from '@data-client/rest';

class Wrapper {
  normalize(
    input: any,
    parent: any,
    key: string,
    delegate: INormalizeDelegate,
  ) {
    const { args, visit } = delegate;
    const normalized = visit(this.schema, input.value, input, 'value');
    delegate.mergeEntity(this, this.pk(input, parent, key, args), normalized);
    return normalized;
  }
}
```

</DiffEditor>

如果你的 schema 接受可选的 `parentEntity` 参数，请把它保留为最后一个参数：

```ts
normalize(input, parent, key, delegate, parentEntity) {
  // ...
}
```

[`delegate.visit()`](/rest/api/SchemaSimple) 在递归规范化时已经携带了同样的参数，因此嵌套的
[schema](/rest/api/schema) 不需要显式传入参数。

#### 新增：normalize 的 `parentEntity` {#additive-parententity-on-normalize}

[normalize delegate](/rest/api/SchemaSimple) 的 `visit()` 回调会在内部跟踪最近的外层
类实体 schema，并将其作为可选的末尾参数 `parentEntity` 转发给 [`Schema.normalize()`](/rest/api/SchemaSimple)。
新的 [schema](/rest/api/schema) 可以选择利用它，在规范化时发现自己所属的实体
（[Scalar](/rest/api/Scalar) 在内部就是这样使用的）。

#### 可选：合并 Collection 定义 {#collection-consolidation}

[`Collection`](/rest/api/Collection) 现在可以在同一个实例上同时使用 [`argsKey`](/rest/api/Collection#argsKey) 和
[`nestKey`](/rest/api/Collection#nestKey)。作为一项可选的
清理，你可以把成对的顶层和嵌套 [Collection](/rest/api/Collection) 替换为一个共享
定义：

<DiffEditor>

```ts title="Before"
export const getTodos = new RestEndpoint({
  path: '/todos',
  searchParams: {} as { userId?: string },
  schema: new Collection([Todo]),
});

class User extends Entity {
  static schema = {
    todos: new Collection([Todo], {
      nestKey: parent => ({ userId: parent.id }),
    }),
  };
}
```

```ts title="After"
export const userTodos = new Collection([Todo], {
  //argsKey: params => ({ ...params }), - this is default, so it's not needed
  nestKey: parent => ({ userId: parent.id }),
});

export const getTodos = new RestEndpoint({
  path: '/todos',
  searchParams: {} as { userId?: string },
  schema: userTodos,
});

class User extends Entity {
  static schema = {
    todos: userTodos,
  };
}
```

</DiffEditor>
