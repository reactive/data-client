## 一致的 null 处理 {#null-consistency}

`null` 值现在在所有 schema 类型中都会被一致地保留。之前，`[]` 简写和 [schema.Array](/rest/api/Array)
在遇到 `null` 值时的行为并不相同。[#2912](https://github.com/reactive/data-client/pull/2912)

- `[]` 和 [schema.Array](/rest/api/Array) 现在行为完全一致
- `null` 值在所有地方都会被保留（在[嵌套 Entity](/rest/guides/relational-data#nesting) 中原本就会保留）
- `undefined` 值仍然会被过滤掉

对于那些显式返回 `null` 表示数据不存在、而用 `undefined` 表示字段缺失的 API，
这一变更确保了更可预测的行为。

## URL 工具函数 {#url-utilities}

### RestEndpoint.searchToString() {#searchtostring}

[RestEndpoint.searchToString()](/rest/api/RestEndpoint#searchToString) 支持对搜索参数进行自定义编码。
这对于期望在查询字符串中接收复杂嵌套对象的 API 尤其有用。
[#2919](https://github.com/reactive/data-client/pull/2919)

例如，使用 [qs](https://github.com/ljharb/qs) 库来编码复杂对象：

```typescript
import { RestEndpoint, RestGenerics } from '@data-client/rest';
import qs from 'qs';

class MyEndpoint<O extends RestGenerics = any> extends RestEndpoint<O> {
  searchToString(searchParams) {
    return qs.stringify(searchParams);
  }
}
```

### getUrlBase、getUrlTokens {#geturlbase}

新导出的 `getUrlBase` 和 `getUrlTokens` 为自定义
[RestEndpoint.url()](/rest/api/RestEndpoint#url) 实现提供了基础构件。
[#2919](https://github.com/reactive/data-client/pull/2919)

```ts
import { getUrlBase, getUrlTokens } from '@data-client/rest';

// Parse path tokens for custom URL logic
const tokens = getUrlTokens('/users/:id/posts/:postId');
// => ['id', 'postId']

// Get base URL without path parameters
const base = getUrlBase('/users/:id');
// => '/users/'
```

### 数组中的 null 值 {#null-arrays}

如果你的代码依赖于 `null` 值被从数组中过滤掉，现在需要显式处理：

<DiffEditor>

```ts title="Before"
import { Entity, schema, RestEndpoint } from '@data-client/rest';

class User extends Entity {
  id = '';
  name = '';
  pk() { return this.id; }
}

const getUsers = new RestEndpoint({
  path: '/users',
  schema: new schema.Array(User),
});

// API response: [{ id: '1' }, null, { id: '2' }]
const usersWithoutNull = useSuspense(getUsers);
```

```ts title="After"
import { Entity, schema, RestEndpoint } from '@data-client/rest';

class User extends Entity {
  id = '';
  name = '';
  pk() { return this.id; }
}

const getUsers = new RestEndpoint({
  path: '/users',
  schema: new schema.Array(User),
});

// API response: [{ id: '1' }, null, { id: '2' }]
const usersWithoutNull = useSuspense(getUsers).filter(Boolean);
```

</DiffEditor>

这一变更与[嵌套 Entity](/rest/guides/relational-data#nesting) 原有的 `null` 处理方式保持一致，
使所有 schema 类型的行为统一。
