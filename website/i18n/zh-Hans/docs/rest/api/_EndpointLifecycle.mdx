### dataExpiryLength?: number {#dataexpirylength}

为所获取资源自定义的数据缓存有效期。会覆盖 NetworkManager 中设置的值。

[进一步了解过期时间](/docs/concepts/expiry-policy#expiry-time)

### errorExpiryLength?: number {#errorexpirylength}

为所获取资源自定义的错误有效期。会覆盖 NetworkManager 中设置的值。

### errorPolicy?: (error: any) => 'soft' | undefined {#errorpolicy}

'soft' 会在出错时使用过时数据（如果存在）；返回 undefined 或不提供该选项时，结果
将是错误。

[进一步了解 errorPolicy](/docs/concepts/error-policy)

```ts
errorPolicy(error) {
  return error.status >= 500 ? 'soft' : undefined;
}
```

### invalidIfStale: boolean {#invalidifstale}

表示过时数据应被视为不可用，因此不会从缓存中返回。这意味着
即使数据已经存在于缓存中，只要它过时了，useSuspense() 就会挂起。

### pollFrequency: number {#pollfrequency}

轮询频率，单位为毫秒。需要配合 [useSubscription()](/docs/api/useSubscription) 或
[useLive()](/docs/api/useLive) 使用才会生效。

### getOptimisticResponse: (snap, ...args) => expectedResponse {#getoptimisticresponse}

提供该函数后，使用此 endpoint 的任何获取都会表现得如同该函数返回的 `expectedResponse`
是一次成功的网络响应。当实际请求完成时（无论失败
还是成功），乐观更新都会被实际的网络响应替换。

`expectedResponse` 会用 endpoint 的 [schema](#schema) 进行规范化，因此 TypeScript 会像检查
[Controller.set()](/docs/api/Controller#set) 的值一样检查它：[Entity](./Entity.md) 接受其任意字段，而
[Collection](./Collection.md) 接受由这些字段组成的列表。当 endpoint 解析为某个特定类型（例如
[process()](./RestEndpoint.md#process) 的返回值）时，它必须改为匹配该类型。

<VoteDemo />

`expectedResponse` 中的 [Entity](./Entity.md) 只需要包含它的[主键](./Entity.md#pk)和发生变化的字段：
省略的字段会保留其缓存值。没有主键时，缓存中的 entity 不会改变，
因此 UI 会等待服务器（开发构建会记录原因）。当 endpoint 的参数不包含该
键时（比如 `PATCH /users/profile`），可以从 [snapshot](/docs/api/Snapshot) 中读取它：

```ts
const getMe = new RestEndpoint({ path: '/users/me', schema: User });
const updateProfile = new RestEndpoint({
  path: '/users/profile',
  method: 'PATCH',
  body: {} as { firstName: string; bio: string },
  schema: User,
  getOptimisticResponse(snap, body) {
    const { data: user } = snap.getResponse(getMe);
    if (!user) throw snap.abort;
    return { id: user.id, ...body };
  },
});
```

当 entity 尚未被缓存时，`throw snap.abort` 会跳过乐观更新。

### update() {#update}

```ts
(normalizedResponseOfThis, ...args) =>
  ({ [endpointKey]: (normalizedResponseOfEndpointToUpdate) => updatedNormalizedResponse) })
```

:::tip

试试改用 [Collections](./Collection.md)。

它们更易用，也更健壮！

:::

```ts title="UpdateType.ts"
type UpdateFunction<
  Source extends EndpointInterface,
  Updaters extends Record<string, any> = Record<string, any>,
> = (
  source: ResultEntry<Source>,
  ...args: Parameters<Source>
) => { [K in keyof Updaters]: (result: Updaters[K]) => Updaters[K] };
```

最简单的情况：

```ts title="userEndpoint.ts"
const createUser = new RestEndpoint({
  path: '/user',
  method: 'POST',
  schema: User,
  update: (newUserId: string) => ({
    [userList.key()]: (users = []) => [newUserId, ...users],
  }),
});
```

更多更新：

:::react

```typescript title="Component.tsx"
const allusers = useSuspense(userList);
const adminUsers = useSuspense(userList, { admin: true });
```

:::vue

```html title="Component.vue"
<script setup lang="ts">
  import { useFetch, useSuspense } from '@data-client/vue';
```

下面的 endpoint 确保新用户会立即出现在上述用法中。

```ts title="userEndpoint.ts"
const createUser = new RestEndpoint({
  path: '/user',
  method: 'POST',
  schema: User,
  update: (newUserId, newUser)  => {
    const updates = {
      [userList.key()]: (users = []) => [newUserId, ...users],
    ];
    if (newUser.isAdmin) {
      updates[userList.key({ admin: true })] = (users = []) => [newUserId, ...users];
    }
    return updates;
  },
});
```
