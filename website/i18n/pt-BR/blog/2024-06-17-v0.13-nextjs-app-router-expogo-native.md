## Plataformas {#platforms}

### NextJS App Router {#nextjs-app-router}

O NextJS 12 inclui uma [nova forma de roteamento no diretório '/app'](https://nextjs.org/docs/app). Isso permite mais melhorias de desempenho, além de roteamento dinâmico e aninhado. Isso torna o NextJS uma plataforma viável para construir aplicações ricas e dinâmicas, e não
apenas sites estáticos.

Enquanto [outros métodos de busca](https://nextjs.org/docs/app/building-your-application/data-fetching/fetching#fetching-data-on-the-client)
exigem uma busca lenta no lado do cliente, o Reactive Data Client oferece o melhor de <abbr title="Single Page Application">SPA</abbr> e
<abbr title="Multi Page Application">MPA</abbr>. [#3074](https://github.com/reactive/data-client/pull/3074), [#3093](https://github.com/reactive/data-client/pull/3093)

Como as MPAs, o SSR com Data Client significa o *carregamento inicial da página* mais rápido possível. Como as SPAs, o Data Client oferece
*navegação*, *mutações no lado do cliente* e *mutações disparadas remotamente* (como websockets) mais rápidas do que as MPAs.

Além disso, o Data Client com SSR continua oferecendo as vantagens de desempenho sobre outras bibliotecas de busca
no lado do cliente.

O <abbr title="Reactive Data Client">Data Client</abbr> realiza SSR em streaming do HTML, agilizando a experiência de carregamento
inicial da aplicação. De forma única, o <abbr title="Reactive Data Client">Data Client</abbr> fica então imediatamente interativo
com 0 buscas no lado do cliente. Isso é alcançado inicializando a [store do cliente](/docs/getting-started/debugging#state-inspection)
com [dados normalizados](/docs/concepts/normalization) durante a fase de SSR.

#### Uso {#usage}

Renderize o [DataProvider](/docs/api/DataProvider) do [ponto de entrada /nextjs](https://dataclient.io/docs/guides/ssr#app-router) no seu [layout raiz](https://nextjs.org/docs/app/building-your-application/routing/pages-and-layouts#root-layout-required).


```tsx title="app/layout.tsx"
import { DataProvider } from '@data-client/react/nextjs';
import { AsyncBoundary } from '@data-client/react';

export default function RootLayout({ children }) {
  return (
    <html>
      <body>
        // highlight-next-line
        <DataProvider>
          <header>Title</header>
          <AsyncBoundary>{children}</AsyncBoundary>
          <footer></footer>
          // highlight-next-line
        </DataProvider>
      </body>
    </html>
  );
}
```

### React 19 {#react-19}

Agora damos suporte ao React 19. [#3071](https://github.com/reactive/data-client/pull/3071)

Isso exigiu abandonar o suporte a versões anteriores à 16.14, já que precisamos usar o runtime de jsx
exportado pelo próprio React. Isso tem o benefício adicional de reduzir o tamanho do bundle.

## controller.set() {#controllerset}

[controller.set()](/docs/api/Controller#set) atualiza qualquer [Schema](/rest/api/schema#schema-overview) [Queryable](/rest/api/schema#queryable). [#3105](https://github.com/reactive/data-client/pull/3105), [#3129](https://github.com/reactive/data-client/pull/3129)

```ts
ctrl.set(
  Todo,
  { id: '5' },
  { id: '5', title: 'tell me friends how great Data Client is' },
);
```

Funções podem ser usadas no valor quando há dados derivados. Isso [evita condições de corrida](https://react.dev/reference/react/useState#updating-state-based-on-the-previous-state).

```ts
const id = '2';
ctrl.set(Article, { id }, article => ({ id, votes: article.votes + 1 }));
```

:::note

A resposta deve incluir valores suficientes para calcular Entity.pk()

:::

Isso torna mais direto manipular a store com [Managers](/docs/concepts/managers).

## Mudanças no REST {#rest-changes}

### Strings de path {#path-strings}

Suporte a + e \* e \{} em [RestEndpoint.path](/rest/api/RestEndpoint#path). [`a6b4f4a`](https://github.com/reactive/data-client/commit/a6b4f4aabbfd06f5106a96e809a6c1a5e7045172)

  ```ts
  const getThing = new RestEndpoint({
    path: '/:attr1?{-:attr2}?{-:attr3}?',
  });

  getThing({ attr1: 'hi' });
  getThing({ attr2: 'hi' });
  getThing({ attr3: 'hi' });
  getThing({ attr1: 'hi', attr3: 'ho' });
  getThing({ attr2: 'hi', attr3: 'ho' });
  ```

### ctrl.fetch() e Unions {#ctrlfetch-and-unions}

Valores de [Unions](/rest/api/Union) no valor de retorno de [ctrl.fetch()](/docs/api/Controller#fetch) agora são uma instância de sua classe Entity. [#3063](https://github.com/reactive/data-client/pull/3063)

<TypeScriptEditor>

```ts title="Feed" collapsed
export abstract class FeedItem extends Entity {
  id = 0;
  declare type: 'link' | 'post';
}
export class Link extends FeedItem {
  readonly type = 'link';
  url = '';
  title = '';

  get anchor() {
    return `<a href="${this.url}">${this.title}</a>`;
  }
}
export class Post extends FeedItem {
  readonly type = 'post';
  content = '';
}
export const getFeed = new RestEndpoint({
  path: '/feed',
  schema: [new schema.Union(
    {
      link: Link,
      post: Post,
    },
    'type',
  )],
});
```

```ts title="useFeed"
import { getFeed } from './Feed';

function useFeedHandler() {
  const ctrl = useController();

  const handleSomething = async () => {
    const feed = await ctrl.fetch(getFeed);
    return feed.map(item => {
      if (item.type == 'link') {
        // we can use class defined getter
        return item.anchor;
      }
    });
  }
  return handleSomething;
}
```

</TypeScriptEditor>

### actionTypes.SET_TYPE -> actionTypes.SET_RESPONSE_TYPE {#set_response_type}

Se você escreveu um Manager personalizado que tratava `actionTypes.SET_TYPE`, precisará
renomeá-lo para [actionTypes.SET_RESPONSE_TYPE](/docs/api/Actions#set_response).

<DiffEditor>

```tsx title="Before"
import type { Manager, Middleware } from '@data-client/react';
import { actionTypes } from '@data-client/react';

export default class LoggingManager implements Manager {
  middleware: Middleware = controller => next => async action => {
    switch (action.type) {
      case actionTypes.SET_TYPE:
        console.info(
          `${action.endpoint.name} ${JSON.stringify(action.response)}`,
        );
        return next(action);
      // actions must be explicitly passed to next middleware
      default:
        return next(action);
    }
  };

  cleanup() {}
}
```

```tsx title="After"
import type { Manager, Middleware } from '@data-client/react';
import { actionTypes } from '@data-client/react';

export default class LoggingManager implements Manager {
  middleware: Middleware = controller => next => async action => {
    switch (action.type) {
      case actionTypes.SET_RESPONSE_TYPE:
        console.info(
          `${action.endpoint.name} ${JSON.stringify(action.response)}`,
        );
        return next(action);
      // actions must be explicitly passed to next middleware
      default:
        return next(action);
    }
  };

  cleanup() {}
}
```

</DiffEditor>

### CacheProvider -> DataProvider {#data-provider}

Migre para o [DataProvider](/docs/api/DataProvider) para garantir compatibilidade com versões futuras. Ele também
é exportado como `CacheProvider`, então esta não é uma mudança incompatível. [#3095](https://github.com/reactive/data-client/pull/3095)

<DiffEditor>

```tsx title="Before"
import { CacheProvider } from '@data-client/react';
import ReactDOM from 'react-dom';

ReactDOM.createRoot(document.body)
  .render(
  <CacheProvider>
    <App />
  </CacheProvider>,
);
```

```tsx title="Before"
import { DataProvider } from '@data-client/react';
import ReactDOM from 'react-dom';

ReactDOM.createRoot(document.body)
  .render(
  <DataProvider>
    <App />
  </DataProvider>,
);
```

</DiffEditor>
