Esta versão foca na experiência do desenvolvedor, com um [botão de devtools](/blog/2024/01/15/v0.9-release-announcement#devtools-button) que aparece em modo de

[Resource.extend()](/rest/api/resource#extend) oferece três maneiras poderosas de personalizar resources - adicionar novos endpoints,
sobrescrever os existentes ou derivar a partir dos endpoints de base.

```ts
const UserResource = createResource({
  path: '/users/:id',
  schema: User,
}).extend('current', {
  path: '/users/current',
});
```

## Resource.extend() <small>(desde 0.5)</small> {#resourceextend}

[Resource.extend()](/rest/api/resource#extend) oferece três maneiras poderosas de personalizar resources.
[51b4b0d](https://github.com/reactive/data-client/commit/51b4b0d188)

### Adicionar novos endpoints {#add-new-endpoints}

```ts
const UserResource = createResource({
  path: '/users/:id',
  schema: User,
}).extend('current', {
  path: '/users/current',
});
```

### Sobrescrever endpoints existentes {#override-existing-endpoints}

```ts
const CachedArticleResource = ArticleResource.extend({
  getList: {
    dataExpiryLength: 10 * 60 * 1000, // 10 minutes
  },
});
```

### Derivar a partir dos endpoints de base {#derive-from-base-endpoints}

```ts
const IssueResource = createResource({
  path: '/issues/:id',
  schema: Issue,
}).extend(Base => ({
  byRepo: Base.getList.extend({
    path: '/repos/:owner/:repo/issues',
  }),
}));
```

## Métodos do Controller {#controller-methods}

### controller.expireAll() <small>(desde 0.3)</small> {#controllerexpireall}

Marca todas as respostas correspondentes como *desatualizadas*, disparando um refetch em segundo plano enquanto exibe os dados existentes.
[#2802](https://github.com/reactive/data-client/pull/2802)

```ts
// Mark all article lists as stale - they'll refetch when rendered
controller.expireAll(ArticleResource.getList);
```

Isso difere de `invalidateAll()`, que remove os dados por completo. `expireAll()` continua exibindo
os dados em cache enquanto busca dados novos em segundo plano.

### controller.fetchIfStale() <small>(desde 0.4)</small> {#controllerfetchifstale}

Busca apenas se os dados forem considerados desatualizados; caso contrário, retorna os dados em cache.
[#2804](https://github.com/reactive/data-client/pull/2804)

```ts
// Perfect for prefetching - won't overfetch fresh data
const resolveData = async (controller, { owner, repo }) => {
  await controller.fetchIfStale(IssueResource.getList, { owner, repo });
};
```

## Melhorias no DevTools {#devtools-improvements}

### Botão do DevTools {#devtools-button}

Um botão flutuante agora aparece em modo de desenvolvimento para abrir rapidamente a extensão Redux DevTools.
[#2803](https://github.com/reactive/data-client/pull/2803)

Configure-o ou desabilite-o pela prop `devButton`:

```tsx
// Disable the button
<CacheProvider devButton={null}>
  <App />
</CacheProvider>
```

```tsx
// Position it differently
<CacheProvider devButton="top-right">
  <App />
</CacheProvider>
```

### Histórico persistente {#persistent-history}

O DevTools não esquece mais o histórico se não estiver aberto no carregamento da página.
[2d2e941](https://github.com/reactive/data-client/commit/2d2e94126e)

### Melhor rastreamento de estado {#better-state-tracking}

Como o React 18 agrupa atualizações em lote, o estado real às vezes pode ser atualizado a partir de várias actions.
Quando o devtools está aberto, um estado sombra reflete com precisão as mudanças de cada action, facilitando a depuração.
[c9ca31f](https://github.com/reactive/data-client/commit/c9ca31f3f4)

### Propriedades de Endpoint visíveis {#endpoint-properties-visible}

As propriedades de Endpoint agora ficam totalmente visíveis no inspetor do devtool.
[a7da00e](https://github.com/reactive/data-client/commit/a7da00e82d)

## Aprimoramentos em Collection {#collection-enhancements}

### Filtragem por argumentos FormData <small>(desde 0.4)</small> {#formdataargumentfiltering}

[Collections](/rest/api/Collection) agora podem filtrar com base em argumentos FormData. [f95dbc6](https://github.com/reactive/data-client/commit/f95dbc64d1)

```ts
ctrl.fetch(getPosts.push, { group: 'react' }, new FormData(e.currentTarget));
```

Se o FormData contiver um campo `author`, o item recém-criado será adicionado corretamente às
collections filtradas por esse autor.

### paginationField <small>(desde 0.7)</small> {#paginationfield}

Use [paginationField](/rest/api/RestEndpoint#paginationfield) para um suporte fácil à paginação.
[c8c557](https://github.com/reactive/data-client/commit/c8c5575e5a)

```ts
const TodoResource = createResource({
  path: '/todos/:id',
  schema: Todo,
  paginationField: 'page',
});

// Fetches page 2 and appends to the collection
ctrl.fetch(TodoResource.getList.getPage, { page: '2' });
```

### Remoção dos exports /next {#remove-next-exports}

Todos os exports de subcaminho `/next` foram removidos. Os recursos que antes estavam em `/next` agora são
os exports padrão. [f65cf83](https://github.com/reactive/data-client/commit/f65cf832f0)

<DiffEditor>

```ts title="Before"
import { useController } from '@data-client/react/next';
```

```ts title="After"
import { useController } from '@data-client/react';
```

</DiffEditor>

### makeCacheProvider removido {#makecacheprovider-removed}

Use o componente provider diretamente com makeRenderDataClient.
[#2787](https://github.com/reactive/data-client/pull/2787)

<DiffEditor>

```tsx title="Before"
import { makeCacheProvider } from '@data-client/react';
const renderDataClient = makeRenderDataClient(makeCacheProvider);
```

```tsx title="After"
import { CacheProvider } from '@data-client/react';
const renderDataClient = makeRenderDataClient(CacheProvider);
```

</DiffEditor>

### Tipo de action DELETE -> INVALIDATE {#delete-invalidate}

O tipo de action DELETE foi renomeado para INVALIDATE por clareza.
[#2784](https://github.com/reactive/data-client/pull/2784)

<DiffEditor>

```ts title="Before"
import { DELETE_TYPE } from '@data-client/react';
```

```ts title="After"
import { INVALIDATE_TYPE } from '@data-client/react';
```

</DiffEditor>

### Suporte a schemas legados descontinuado {#legacy-schema-support-dropped}

Todo o suporte a schemas legados foi removido. Certifique-se de estar usando a classe
Entity atual. [#2784](https://github.com/reactive/data-client/pull/2784)

- `entity.expiresAt` removido
- Todas as sobrescritas de Entity para compatibilidade retroativa foram removidas

### Serializadores de Schema devem suportar chamadas de função {#schema-serializers}

Os [serializadores de Schema](/rest/guides/network-transform#deserializing-fields) agora devem suportar
chamadas de função. `Date` não funciona mais diretamente. [#2795](https://github.com/reactive/data-client/pull/2795)

<DiffEditor>

```ts title="Before"
class MyEntity extends Entity {
  createdAt = new Date();

  static schema = {
    // highlight-next-line
    createdAt: Date,
  };
}
```

```ts title="After"
class MyEntity extends Entity {
  createdAt = new Date();

  static schema = {
    // highlight-next-line
    createdAt: (iso: string) => new Date(iso),
  };
}
```

</DiffEditor>

Como alternativa, use Temporal:

```ts
import { Temporal } from 'temporal-polyfill';

class MyEntity extends Entity {
  createdAt = Temporal.Instant.fromEpochSeconds(0);

  static schema = {
    createdAt: Temporal.Instant.from,
  };
}
```

### Tipos de action prefixados com 'rdc' {#action-types-prefix}

Todos os tipos de action agora são prefixados com 'rdc' para um melhor namespacing.
[#2781](https://github.com/reactive/data-client/pull/2781)

### Nomes de action receive -> set {#receive---set-action-names}

Todos os nomes de action 'receive' foram renomeados para 'set'.
[#2782](https://github.com/reactive/data-client/pull/2782)

<DiffEditor>

```ts title="Before"
import { ReceiveAction, RECEIVE_TYPE } from '@data-client/react';
controller.receive(endpoint, args, response);
```

```ts title="After"
import { SetAction, SET_TYPE } from '@data-client/react';
controller.set(endpoint, args, response);
```

</DiffEditor>

### API de Middleware simplificada {#middleware-api-simplified}

O Middleware não recebe mais `controller` como uma propriedade desestruturada - ele recebe
o controller diretamente. [#2786](https://github.com/reactive/data-client/pull/2786)

<DiffEditor>

```ts title="Before"
class LoggingManager implements Manager {
  // highlight-next-line
  getMiddleware = (): Middleware => ({ controller }) => next => async action => {
    console.log('before', action, controller.getState());
    await next(action);
    console.log('after', action, controller.getState());
  };

  cleanup() {}
}
```

```ts title="After"
class LoggingManager implements Manager {
  // highlight-next-line
  getMiddleware = (): Middleware => controller => next => async action => {
    console.log('before', action, controller.getState());
    await next(action);
    console.log('after', action, controller.getState());
  };

  cleanup() {}
}
```

</DiffEditor>

### getDefaultManagers() {#getdefaultmanagers}

Os elementos CacheProvider não compartilham mais os managers padrão. Use `getDefaultManagers()` para controle explícito.
[#2791](https://github.com/reactive/data-client/pull/2791)

```ts
import { getDefaultManagers, CacheProvider } from '@data-client/react';

const managers = getDefaultManagers();

<CacheProvider managers={managers}>
  <App />
</CacheProvider>
```
