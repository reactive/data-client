## Tratamento consistente de null {#null-consistency}

Valores `null` agora são mantidos de forma consistente em todos os tipos de schema. Antes, o atalho `[]` e [schema.Array](/rest/api/Array)
se comportavam de maneira diferente ao encontrar valores `null`. [#2912](https://github.com/reactive/data-client/pull/2912)

- `[]` e [schema.Array](/rest/api/Array) agora se comportam de forma idêntica
- Valores `null` são mantidos em todos os lugares (já eram mantidos em [Entities aninhadas](/rest/guides/relational-data#nesting))
- Valores `undefined` continuam sendo filtrados

Essa mudança garante um comportamento mais previsível ao trabalhar com APIs que retornam `null` explicitamente para indicar
ausência de dados, em contraste com `undefined` para campos faltantes.

## Utilitários de URL {#url-utilities}

### RestEndpoint.searchToString() {#searchtostring}

[RestEndpoint.searchToString()](/rest/api/RestEndpoint#searchToString) permite a codificação personalizada dos parâmetros de busca.
Isso é especialmente útil para APIs que esperam objetos aninhados complexos nas query strings.
[#2919](https://github.com/reactive/data-client/pull/2919)

Por exemplo, para codificar objetos complexos usando a biblioteca [qs](https://github.com/ljharb/qs):

```typescript
import { RestEndpoint, RestGenerics } from '@data-client/rest';
import qs from 'qs';

class MyEndpoint<O extends RestGenerics = any> extends RestEndpoint<O> {
  searchToString(searchParams) {
    return qs.stringify(searchParams);
  }
}
```

### getUrlBase, getUrlTokens {#geturlbase}

Os novos exports `getUrlBase` e `getUrlTokens` fornecem os blocos de construção para implementações personalizadas de
[RestEndpoint.url()](/rest/api/RestEndpoint#url).
[#2919](https://github.com/reactive/data-client/pull/2919)

```ts
import { getUrlBase, getUrlTokens } from '@data-client/rest';

// Parse path tokens for custom URL logic
const tokens = getUrlTokens('/users/:id/posts/:postId');
// => ['id', 'postId']

// Get base URL without path parameters
const base = getUrlBase('/users/:id');
// => '/users/'
```

## Correção de memória no DevToolsManager {#devtools-fix}

O buffer de actions do DevToolsManager agora é limitado a 100 entradas, evitando vazamentos de memória em aplicações de longa duração
ou com atualizações frequentes. [`4e6a39e`](https://github.com/reactive/data-client/commit/4e6a39ea2bfdb1390051f12781e899488609e1a8)

### Valores null em arrays {#null-arrays}

Se o seu código dependia de valores `null` serem filtrados dos arrays, você precisará tratar isso explicitamente:

<DiffEditor>

```ts title="Before"
import { Entity, schema, RestEndpoint } from '@data-client/rest';

class User extends Entity {
  id = '';
  name = '';
  pk() { return this.id; }
}

const getUsers = new RestEndpoint({
  path: '/users',
  schema: new schema.Array(User),
});

// API response: [{ id: '1' }, null, { id: '2' }]
const usersWithoutNull = useSuspense(getUsers);
```

```ts title="After"
import { Entity, schema, RestEndpoint } from '@data-client/rest';

class User extends Entity {
  id = '';
  name = '';
  pk() { return this.id; }
}

const getUsers = new RestEndpoint({
  path: '/users',
  schema: new schema.Array(User),
});

// API response: [{ id: '1' }, null, { id: '2' }]
const usersWithoutNull = useSuspense(getUsers).filter(Boolean);
```

</DiffEditor>

Essa mudança se alinha a como as [Entities aninhadas](/rest/guides/relational-data#nesting) já tratavam valores `null`,
tornando o comportamento consistente em todos os tipos de schema.
