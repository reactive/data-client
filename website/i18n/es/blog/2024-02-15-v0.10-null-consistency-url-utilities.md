## Manejo consistente de null {#null-consistency}

Los valores `null` ahora se conservan de forma consistente en todos los tipos de schema. Antes, la abreviatura `[]` y [schema.Array](/rest/api/Array)
se comportaban de manera distinta al encontrar valores `null`. [#2912](https://github.com/reactive/data-client/pull/2912)

- `[]` y [schema.Array](/rest/api/Array) ahora se comportan de forma idéntica
- Los valores `null` se conservan en todas partes (ya se conservaban en las [Entities anidadas](/rest/guides/relational-data#nesting))
- Los valores `undefined` siguen filtrándose

Este cambio garantiza un comportamiento más predecible al trabajar con APIs que devuelven `null` explícitamente para indicar
ausencia de datos frente a `undefined` para campos faltantes.

## Utilidades de URL {#url-utilities}

### RestEndpoint.searchToString() {#searchtostring}

[RestEndpoint.searchToString()](/rest/api/RestEndpoint#searchToString) permite codificar los parámetros de búsqueda de forma personalizada.
Esto es especialmente útil para APIs que esperan objetos anidados complejos en las cadenas de consulta.
[#2919](https://github.com/reactive/data-client/pull/2919)

Por ejemplo, para codificar objetos complejos con la biblioteca [qs](https://github.com/ljharb/qs):

```typescript
import { RestEndpoint, RestGenerics } from '@data-client/rest';
import qs from 'qs';

class MyEndpoint<O extends RestGenerics = any> extends RestEndpoint<O> {
  searchToString(searchParams) {
    return qs.stringify(searchParams);
  }
}
```

### getUrlBase, getUrlTokens {#geturlbase}

Las nuevas exportaciones `getUrlBase` y `getUrlTokens` proporcionan los bloques de construcción para implementaciones
personalizadas de [RestEndpoint.url()](/rest/api/RestEndpoint#url).
[#2919](https://github.com/reactive/data-client/pull/2919)

```ts
import { getUrlBase, getUrlTokens } from '@data-client/rest';

// Parse path tokens for custom URL logic
const tokens = getUrlTokens('/users/:id/posts/:postId');
// => ['id', 'postId']

// Get base URL without path parameters
const base = getUrlBase('/users/:id');
// => '/users/'
```

## Corrección de memoria en DevToolsManager {#devtools-fix}

El búfer de acciones de DevToolsManager ahora está limitado a 100 entradas, lo que evita fugas de memoria en aplicaciones
de larga duración o con actualizaciones frecuentes. [`4e6a39e`](https://github.com/reactive/data-client/commit/4e6a39ea2bfdb1390051f12781e899488609e1a8)

### Valores null en arreglos {#null-arrays}

Si tu código dependía de que los valores `null` se filtraran de los arreglos, tendrás que manejarlo explícitamente:

<DiffEditor>

```ts title="Before"
import { Entity, schema, RestEndpoint } from '@data-client/rest';

class User extends Entity {
  id = '';
  name = '';
  pk() { return this.id; }
}

const getUsers = new RestEndpoint({
  path: '/users',
  schema: new schema.Array(User),
});

// API response: [{ id: '1' }, null, { id: '2' }]
const usersWithoutNull = useSuspense(getUsers);
```

```ts title="After"
import { Entity, schema, RestEndpoint } from '@data-client/rest';

class User extends Entity {
  id = '';
  name = '';
  pk() { return this.id; }
}

const getUsers = new RestEndpoint({
  path: '/users',
  schema: new schema.Array(User),
});

// API response: [{ id: '1' }, null, { id: '2' }]
const usersWithoutNull = useSuspense(getUsers).filter(Boolean);
```

</DiffEditor>

Este cambio se alinea con la forma en que las [Entities anidadas](/rest/guides/relational-data#nesting) ya manejaban los valores `null`,
haciendo que el comportamiento sea consistente en todos los tipos de schema.
