## Plataformas {#platforms}

### NextJS App Router {#nextjs-app-router}

NextJS 12 incluye una [nueva forma de enrutamiento en el directorio '/app'](https://nextjs.org/docs/app). Esto permite más mejoras de rendimiento, así como enrutamiento dinámico y anidado. Esto convierte a NextJS en una plataforma viable para construir aplicaciones dinámicas ricas, en lugar
de solo sitios web estáticos.

Mientras que [otros métodos de obtención de datos](https://nextjs.org/docs/app/building-your-application/data-fetching/fetching#fetching-data-on-the-client)
requieren una lenta obtención del lado del cliente, Reactive Data Client ofrece lo mejor de las <abbr title="Aplicación de una sola página">SPA</abbr> y de las
<abbr title="Aplicación de múltiples páginas">MPA</abbr>. [#3074](https://github.com/reactive/data-client/pull/3074), [#3093](https://github.com/reactive/data-client/pull/3093)

Como las MPA, el SSR con Data Client significa la *carga inicial de página* más rápida posible. Como las SPA, Data Client ofrece una
*navegación*, unas *mutaciones del lado del cliente* y unas *mutaciones impulsadas desde el servidor* (como websockets) más rápidas que las MPA.

Además, Data Client con SSR sigue ofreciendo las ventajas de rendimiento frente a otras bibliotecas de obtención de datos
del lado del cliente.

<abbr title="Reactive Data Client">Data Client</abbr> realiza SSR en streaming del HTML, agilizando la experiencia de carga inicial
de la aplicación. De forma única, <abbr title="Reactive Data Client">Data Client</abbr> queda entonces interactivo de inmediato
con 0 obtenciones de datos del lado del cliente. Esto se logra inicializando el [Store del cliente](/docs/getting-started/debugging#state-inspection)
con [datos normalizados](/docs/concepts/normalization) durante la fase de SSR.

#### Uso {#usage}

Renderiza [DataProvider](/docs/api/DataProvider) desde el [punto de entrada /nextjs](https://dataclient.io/docs/guides/ssr#app-router) en tu [layout raíz](https://nextjs.org/docs/app/building-your-application/routing/pages-and-layouts#root-layout-required).


```tsx title="app/layout.tsx"
import { DataProvider } from '@data-client/react/nextjs';
import { AsyncBoundary } from '@data-client/react';

export default function RootLayout({ children }) {
  return (
    <html>
      <body>
        // highlight-next-line
        <DataProvider>
          <header>Title</header>
          <AsyncBoundary>{children}</AsyncBoundary>
          <footer></footer>
          // highlight-next-line
        </DataProvider>
      </body>
    </html>
  );
}
```

### React 19 {#react-19}

Ahora admitimos React 19. [#3071](https://github.com/reactive/data-client/pull/3071)

Esto requirió abandonar el soporte para versiones anteriores a 16.14, ya que debemos usar el runtime de jsx
exportado por el propio React. Esto tiene el beneficio adicional de reducir el tamaño del bundle.

## controller.set() {#controllerset}

[controller.set()](/docs/api/Controller#set) actualiza cualquier [Schema](/rest/api/schema#schema-overview) [Queryable](/rest/api/schema#queryable). [#3105](https://github.com/reactive/data-client/pull/3105), [#3129](https://github.com/reactive/data-client/pull/3129)

```ts
ctrl.set(
  Todo,
  { id: '5' },
  { id: '5', title: 'tell me friends how great Data Client is' },
);
```

Se pueden usar funciones como valor cuando se trabaja con datos derivados. Esto [evita condiciones de carrera](https://react.dev/reference/react/useState#updating-state-based-on-the-previous-state).

```ts
const id = '2';
ctrl.set(Article, { id }, article => ({ id, votes: article.votes + 1 }));
```

:::note

La respuesta debe incluir valores suficientes para calcular Entity.pk()

:::

Esto hace más directo manipular el store con [Managers](/docs/concepts/managers).

## Cambios en REST {#rest-changes}

### Cadenas de path {#path-strings}

Se admiten + y \* y \{} en [RestEndpoint.path](/rest/api/RestEndpoint#path). [`a6b4f4a`](https://github.com/reactive/data-client/commit/a6b4f4aabbfd06f5106a96e809a6c1a5e7045172)

  ```ts
  const getThing = new RestEndpoint({
    path: '/:attr1?{-:attr2}?{-:attr3}?',
  });

  getThing({ attr1: 'hi' });
  getThing({ attr2: 'hi' });
  getThing({ attr3: 'hi' });
  getThing({ attr1: 'hi', attr3: 'ho' });
  getThing({ attr2: 'hi', attr3: 'ho' });
  ```

### ctrl.fetch() y Unions {#ctrlfetch-and-unions}

Los valores de [Unions](/rest/api/Union) en el valor de retorno de [ctrl.fetch()](/docs/api/Controller#fetch) ahora son una instancia de su clase Entity. [#3063](https://github.com/reactive/data-client/pull/3063)

<TypeScriptEditor>

```ts title="Feed" collapsed
export abstract class FeedItem extends Entity {
  id = 0;
  declare type: 'link' | 'post';
}
export class Link extends FeedItem {
  readonly type = 'link';
  url = '';
  title = '';

  get anchor() {
    return `<a href="${this.url}">${this.title}</a>`;
  }
}
export class Post extends FeedItem {
  readonly type = 'post';
  content = '';
}
export const getFeed = new RestEndpoint({
  path: '/feed',
  schema: [new schema.Union(
    {
      link: Link,
      post: Post,
    },
    'type',
  )],
});
```

```ts title="useFeed"
import { getFeed } from './Feed';

function useFeedHandler() {
  const ctrl = useController();

  const handleSomething = async () => {
    const feed = await ctrl.fetch(getFeed);
    return feed.map(item => {
      if (item.type == 'link') {
        // we can use class defined getter
        return item.anchor;
      }
    });
  }
  return handleSomething;
}
```

</TypeScriptEditor>

### actionTypes.SET_TYPE -> actionTypes.SET_RESPONSE_TYPE {#set_response_type}

Si escribiste un Manager personalizado que manejaba `actionTypes.SET_TYPE`, tendrás que
renombrarlo a [actionTypes.SET_RESPONSE_TYPE](/docs/api/Actions#set_response).

<DiffEditor>

```tsx title="Before"
import type { Manager, Middleware } from '@data-client/react';
import { actionTypes } from '@data-client/react';

export default class LoggingManager implements Manager {
  middleware: Middleware = controller => next => async action => {
    switch (action.type) {
      case actionTypes.SET_TYPE:
        console.info(
          `${action.endpoint.name} ${JSON.stringify(action.response)}`,
        );
        return next(action);
      // actions must be explicitly passed to next middleware
      default:
        return next(action);
    }
  };

  cleanup() {}
}
```

```tsx title="After"
import type { Manager, Middleware } from '@data-client/react';
import { actionTypes } from '@data-client/react';

export default class LoggingManager implements Manager {
  middleware: Middleware = controller => next => async action => {
    switch (action.type) {
      case actionTypes.SET_RESPONSE_TYPE:
        console.info(
          `${action.endpoint.name} ${JSON.stringify(action.response)}`,
        );
        return next(action);
      // actions must be explicitly passed to next middleware
      default:
        return next(action);
    }
  };

  cleanup() {}
}
```

</DiffEditor>

### CacheProvider -> DataProvider {#data-provider}

Pásate a [DataProvider](/docs/api/DataProvider) para mantener la compatibilidad con versiones futuras. También se
exporta como `CacheProvider`, así que no es un cambio incompatible. [#3095](https://github.com/reactive/data-client/pull/3095)

<DiffEditor>

```tsx title="Before"
import { CacheProvider } from '@data-client/react';
import ReactDOM from 'react-dom';

ReactDOM.createRoot(document.body)
  .render(
  <CacheProvider>
    <App />
  </CacheProvider>,
);
```

```tsx title="Before"
import { DataProvider } from '@data-client/react';
import ReactDOM from 'react-dom';

ReactDOM.createRoot(document.body)
  .render(
  <DataProvider>
    <App />
  </DataProvider>,
);
```

</DiffEditor>
