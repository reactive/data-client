Esta versión se centra en la experiencia de desarrollo con un [botón de devtools](/blog/2024/01/15/v0.9-release-announcement#devtools-button) que aparece en modo
de desarrollo, un mejor [historial de DevTools](/blog/2024/01/15/v0.9-release-announcement#devtools-improvements) y nuevos métodos del controller como
[controller.expireAll()](/blog/2024/01/15/v0.9-release-announcement#controllerexpireall) y [controller.fetchIfStale()](/blog/2024/01/15/v0.9-release-announcement#controllerfetchifstale).

[Resource.extend()](/rest/api/resource#extend) ofrece tres formas potentes de personalizar recursos: agregar nuevos endpoints,
sobrescribir los existentes o derivar a partir de los endpoints base.

```ts
const UserResource = createResource({
  path: '/users/:id',
  schema: User,
}).extend('current', {
  path: '/users/current',
});
```

## Resource.extend() <small>(desde 0.5)</small> {#resourceextend}

[Resource.extend()](/rest/api/resource#extend) ofrece tres formas potentes de personalizar recursos.
[51b4b0d](https://github.com/reactive/data-client/commit/51b4b0d188)

### Agregar nuevos endpoints {#add-new-endpoints}

```ts
const UserResource = createResource({
  path: '/users/:id',
  schema: User,
}).extend('current', {
  path: '/users/current',
});
```

### Sobrescribir endpoints existentes {#override-existing-endpoints}

```ts
const CachedArticleResource = ArticleResource.extend({
  getList: {
    dataExpiryLength: 10 * 60 * 1000, // 10 minutes
  },
});
```

### Derivar a partir de los endpoints base {#derive-from-base-endpoints}

```ts
const IssueResource = createResource({
  path: '/issues/:id',
  schema: Issue,
}).extend(Base => ({
  byRepo: Base.getList.extend({
    path: '/repos/:owner/:repo/issues',
  }),
}));
```

## Métodos del Controller {#controller-methods}

### controller.expireAll() <small>(desde 0.3)</small> {#controllerexpireall}

Marca todas las respuestas coincidentes como *obsoletas*, lo que dispara una nueva obtención en segundo plano mientras se muestran los datos existentes.
[#2802](https://github.com/reactive/data-client/pull/2802)

```ts
// Mark all article lists as stale - they'll refetch when rendered
controller.expireAll(ArticleResource.getList);
```

Esto difiere de `invalidateAll()`, que elimina los datos por completo. `expireAll()` sigue mostrando
los datos en caché mientras obtiene datos frescos en segundo plano.

### controller.fetchIfStale() <small>(desde 0.4)</small> {#controllerfetchifstale}

Obtiene los datos solo si se consideran obsoletos; de lo contrario, devuelve los datos en caché.
[#2804](https://github.com/reactive/data-client/pull/2804)

```ts
// Perfect for prefetching - won't overfetch fresh data
const resolveData = async (controller, { owner, repo }) => {
  await controller.fetchIfStale(IssueResource.getList, { owner, repo });
};
```

## Mejoras en DevTools {#devtools-improvements}

### Botón de DevTools {#devtools-button}

Ahora aparece un botón flotante en modo de desarrollo para abrir rápidamente la extensión Redux DevTools.
[#2803](https://github.com/reactive/data-client/pull/2803)

Configúralo o desactívalo con la prop `devButton`:

```tsx
// Disable the button
<CacheProvider devButton={null}>
  <App />
</CacheProvider>
```

```tsx
// Position it differently
<CacheProvider devButton="top-right">
  <App />
</CacheProvider>
```

### Historial persistente {#persistent-history}

DevTools ya no olvida el historial si no estaba abierto al cargar la página.
[2d2e941](https://github.com/reactive/data-client/commit/2d2e94126e)

### Mejor seguimiento del estado {#better-state-tracking}

Como React 18 agrupa las actualizaciones, el estado real a veces puede actualizarse a partir de varias acciones.
Cuando las devtools están abiertas, un estado sombra refleja con precisión los cambios de cada acción para facilitar la depuración.
[c9ca31f](https://github.com/reactive/data-client/commit/c9ca31f3f4)

### Propiedades de Endpoint visibles {#endpoint-properties-visible}

Las propiedades de los Endpoints ahora son completamente visibles en el inspector de devtools.
[a7da00e](https://github.com/reactive/data-client/commit/a7da00e82d)

## Mejoras en Collection {#collection-enhancements}

### Filtrado por argumentos FormData <small>(desde 0.4)</small> {#formdataargumentfiltering}

Las [Collections](/rest/api/Collection) ahora pueden filtrar según argumentos FormData. [f95dbc6](https://github.com/reactive/data-client/commit/f95dbc64d1)

```ts
ctrl.fetch(getPosts.push, { group: 'react' }, new FormData(e.currentTarget));
```

Si el FormData contiene un campo `author`, el elemento recién creado se agregará correctamente a
las collections filtradas por ese autor.

### paginationField <small>(desde 0.7)</small> {#paginationfield}

Usa [paginationField](/rest/api/RestEndpoint#paginationfield) para un soporte de paginación sencillo.
[c8c557](https://github.com/reactive/data-client/commit/c8c5575e5a)

```ts
const TodoResource = createResource({
  path: '/todos/:id',
  schema: Todo,
  paginationField: 'page',
});

// Fetches page 2 and appends to the collection
ctrl.fetch(TodoResource.getList.getPage, { page: '2' });
```

## Otras mejoras {#other-improvements}

- Se agrega `className` a ErrorBoundary y `errorClassName` a [AsyncBoundary](/docs/api/AsyncBoundary) [#2785](https://github.com/reactive/data-client/pull/2785)
- Nueva exportación `getDefaultManagers()` para un control explícito de los managers [#2791](https://github.com/reactive/data-client/pull/2791)
- Se reemplaza BackupBoundary por UniversalSuspense + BackupLoading [#2803](https://github.com/reactive/data-client/pull/2803)
- Entity.process() recibe los `args` del endpoint como cuarto parámetro *(desde 0.7)* [a8936f5](https://github.com/reactive/data-client/commit/a8936f5e6d)
- `nonFilterArgumentKeys` en Collection para excluir los parámetros de ordenamiento del filtrado *(desde 0.7)* [318df89](https://github.com/reactive/data-client/commit/318df89bf7)

### Se eliminan las exportaciones /next {#remove-next-exports}

Se eliminaron todas las exportaciones de la subruta `/next`. Las funcionalidades que antes estaban en `/next` ahora son
las exportaciones estándar. [f65cf83](https://github.com/reactive/data-client/commit/f65cf832f0)

<DiffEditor>

```ts title="Before"
import { useController } from '@data-client/react/next';
```

```ts title="After"
import { useController } from '@data-client/react';
```

</DiffEditor>

### makeCacheProvider eliminado {#makecacheprovider-removed}

Usa el componente proveedor directamente con makeRenderDataClient.
[#2787](https://github.com/reactive/data-client/pull/2787)

<DiffEditor>

```tsx title="Before"
import { makeCacheProvider } from '@data-client/react';
const renderDataClient = makeRenderDataClient(makeCacheProvider);
```

```tsx title="After"
import { CacheProvider } from '@data-client/react';
const renderDataClient = makeRenderDataClient(CacheProvider);
```

</DiffEditor>

### Tipo de acción DELETE -> INVALIDATE {#delete-invalidate}

El tipo de acción DELETE pasa a llamarse INVALIDATE para mayor claridad.
[#2784](https://github.com/reactive/data-client/pull/2784)

<DiffEditor>

```ts title="Before"
import { DELETE_TYPE } from '@data-client/react';
```

```ts title="After"
import { INVALIDATE_TYPE } from '@data-client/react';
```

</DiffEditor>

### Se abandona el soporte de schemas heredados {#legacy-schema-support-dropped}

Se eliminó todo el soporte para schemas heredados. Asegúrate de estar usando la clase
Entity actual. [#2784](https://github.com/reactive/data-client/pull/2784)

- `entity.expiresAt` eliminado
- Se eliminan todas las sobrescrituras de Entity que existían por compatibilidad hacia atrás

### Los serializadores de Schema deben admitir llamadas como función {#schema-serializers}

Los [serializadores de Schema](/rest/guides/network-transform#deserializing-fields) ahora deben admitir
llamadas como función. `Date` ya no funciona directamente. [#2795](https://github.com/reactive/data-client/pull/2795)

<DiffEditor>

```ts title="Before"
class MyEntity extends Entity {
  createdAt = new Date();

  static schema = {
    // highlight-next-line
    createdAt: Date,
  };
}
```

```ts title="After"
class MyEntity extends Entity {
  createdAt = new Date();

  static schema = {
    // highlight-next-line
    createdAt: (iso: string) => new Date(iso),
  };
}
```

</DiffEditor>

Como alternativa, usa Temporal:

```ts
import { Temporal } from 'temporal-polyfill';

class MyEntity extends Entity {
  createdAt = Temporal.Instant.fromEpochSeconds(0);

  static schema = {
    createdAt: Temporal.Instant.from,
  };
}
```

### Tipos de acción con el prefijo 'rdc' {#action-types-prefix}

Todos los tipos de acción ahora llevan el prefijo 'rdc' para un mejor espacio de nombres.
[#2781](https://github.com/reactive/data-client/pull/2781)

### Nombres de acción receive -> set {#receive---set-action-names}

Todos los nombres de acción 'receive' pasan a llamarse 'set'.
[#2782](https://github.com/reactive/data-client/pull/2782)

<DiffEditor>

```ts title="Before"
import { ReceiveAction, RECEIVE_TYPE } from '@data-client/react';
controller.receive(endpoint, args, response);
```

```ts title="After"
import { SetAction, SET_TYPE } from '@data-client/react';
controller.set(endpoint, args, response);
```

</DiffEditor>

### API de Middleware simplificada {#middleware-api-simplified}

El Middleware ya no recibe `controller` como una propiedad desestructurada: recibe
el controller directamente. [#2786](https://github.com/reactive/data-client/pull/2786)

<DiffEditor>

```ts title="Before"
class LoggingManager implements Manager {
  // highlight-next-line
  getMiddleware = (): Middleware => ({ controller }) => next => async action => {
    console.log('before', action, controller.getState());
    await next(action);
    console.log('after', action, controller.getState());
  };

  cleanup() {}
}
```

```ts title="After"
class LoggingManager implements Manager {
  // highlight-next-line
  getMiddleware = (): Middleware => controller => next => async action => {
    console.log('before', action, controller.getState());
    await next(action);
    console.log('after', action, controller.getState());
  };

  cleanup() {}
}
```

</DiffEditor>

### getDefaultManagers() {#getdefaultmanagers}

Los elementos CacheProvider ya no comparten los managers predeterminados. Usa `getDefaultManagers()` para un control explícito.
[#2791](https://github.com/reactive/data-client/pull/2791)

```ts
import { getDefaultManagers, CacheProvider } from '@data-client/react';

const managers = getDefaultManagers();

<CacheProvider managers={managers}>
  <App />
</CacheProvider>
```
